# 第四轮审查（2026-10-20）：把「优化引入的回归」从靠人记变成靠机器拦

> 起因：这个项目做过的**每一轮审查都引入了新 bug**。
> 四轮审查、几十条修复，改的每一条都得靠**真机人工验**兜底 ——
> 而真机验不动的部分（尤其是界面观感与宿主行为）就一直是个黑洞。
>
> 这一轮的重点因此不是「又找出多少问题」，而是
> **「下次改错了，能不能在提交前就拦住」**。

## 二、真正的收获：**自查抓不到自己推理链里的漏洞**

这一轮派了**五轮独立只读复核**（每轮换一个维度），结果：

| 轮次 | 维度 | 查出 | 其中「我自己前一轮修出来的」 |
|---|---|---|---|
| 一次 | 这批引入的 | 2 P1 + 7 P2 | 1 |
| 二次 | 这批引入的 | 3 P1 + 5 P2 | 3 |
| 三次 | 这批引入的 | 2 P1 + 7 P2 | 2 |
| 四次 | 还原路径 / 配置一致性 | 2 P0 + 4 P1/P2 | 1 |
| 五次 | **有没有做完**（存在 ≠ 生效） | 1 P0 + 2 P1 + 5 P2 | 1 |
| **合计** | | **10 P0/P1 + 28 P2** | **8** |

**十条 P0/P1 里有八条是我自己在前一轮修出来的。**

最讽刺的一个（第四次审计）：我以为「host 与 target 共用同一个 `LayoutParams` 实例」是隐患，
就去做了拷贝构造 —— **而 `addView` 本来就会自动转副本**，
我的「防御」直接丢掉了宿主筛选面板的 ConstraintLayout 约束。

> **为什么自查抓不到**：每一处改动在我脑子里都是「我刚刚想清楚了的」，
> 于是那些**推理前提站不住**的地方根本不会被自己看见 ——
> 而它们恰恰是「改了判据」最常见的问题形态。

### 所以定了三条规矩

1. **改了判据 → 派独立复核**（prompt 里要写死 `docs/CODE-RULES.md` 的前车之鉴 12 条，
   并限定「只报这批引入的」「换维度查」）；
2. **复核结论必须自己回读代码核实**（它会误报：有一轮它说某个纯函数与实现不等价，
   逐条比对下来四条条件一一对齐）；
3. **再跑变异测试**（见下）。

## 三、装上的防护

### ① 125 条单元测试（`app/src/test/`）

覆盖的是**纯逻辑那一半**（不需要真机就能验的）：
配置指纹、筛选语义真值表、算价引擎、打码、配置键对齐、限速决策、结构判据、字重决策、
连接断开时机、落盘键、方案 JSON 编解码。

### ② 三套静态检查（`tools/ci/`，全接进 CI）

| 脚本 | 查什么 |
|---|---|
| `check_invariants.py` | 8 条不变量：Miuix `Overlay*` 禁用、关键状态用 `rememberSaveable`、自己的类名当判据要有 proguard keep、功能键不能是假开关、宿主标识用候选数组、中英键对齐、日志不得出现裸代码、跨容器搬 View 先摘旧父 |
| `check_switches.py` | 功能开关全链路：目录行 ↔ 配置键 ↔ 快照字段 ↔ 出厂默认值；**外加调试通道的列与值必须等长** |
| `check_contract.py` | 宿主契约：代码里认的宿主标识 ↔ 契约清单（164 条登记） |

### ③ 变异测试（`tools/ci/mutants.py`）—— **这才是关键的一道**

把每个判据**故意改坏一次**，确认对应的测试**真的会红**。

11 个变异体全部被抓住。它当场找出**两个真的守卫盲区**：
「当前已是加粗态时不能把加粗后的记成原字重」与「打码要挡住两位的代码」。

> ⚠️ **变异体没被抓到时，先怀疑变异体本身** ——
> 有一版我写的指纹变异体（每个位乘同一个数）**造不出**碰撞，测试抓不到它是**对的**。
>
> 它会**临时改源码**（跑完自己还原），所以要求工作区是干净的。
> 不是 CI 的常规步骤（要跑 11 遍测试），而是**改了判据之后手动跑一次**的检查清单。

## 四、仍然只能靠真机的那一半

**界面观感**（液态玻璃 / 深色模式 / 字体度量 / 抗锯齿）与**宿主行为**
（视图结构、点击分发、宿主改版后的兼容）—— 自动化帮不上忙。

2026-10-20 实测过 Robolectric：制品能下、纯 View 能跑，但**跑 Compose 界面过不去**
（Activity 解析不了；而官方那个 AAR 是 debug 变体用的，本项目只编 release 变体，
引进 release 等于把一个测试 Activity 打进正式包）。细节见 `app/build.gradle.kts` 依赖处。

**模拟器**也走不通：本机 CPU 虚拟化支持齐全，但 Android Emulator hypervisor driver 没装、
Hyper-V / WHPX 也没启用，而这两样都要管理员权限。

所以这一轮**全部改动都没上过机**（设备 4 小时里一次没上线）。
装机后要重点验什么，逐条写在 `.work/notes/pending-push.md` 末节。

## 五、给下一个人的三句话

1. **改了判据就别信自查** —— 派个只读的子代理复核，prompt 里写死前车之鉴那 12 条。
2. **「存在」不等于「生效」** —— 新增的东西逐个问「谁在调用它」。
   （`DebugConfigProvider` 补了列忘了补值，28 列 vs 15 值 → 整个调试通道读不出配置。）
3. **把判据抽成纯函数 + 写单测 + 跑变异测试** —— 三道关，比多写十行注释有用。

## 六、2026-10-23/24 维护轮：三条老坑的新变种

这一轮不是新功能，是把上一轮审查里「评估后放弃」的中低危清掉。三条教训都值得写进下一轮的自查清单。

### 6.1 只要存在「过滤 / 转换后的列表」，下标必须在同一轮转换里记

`StgDirectQuoteFeature` 的正常路径用对象引用（`===`）在转换时记下标，是对的；
兜底路径却拿「原始列表下标」去索引「转换后的列表」。`toIntentStockInfo` 失败的元素会被
`continue` 跳过，两个列表不等长 —— 筛选生效且有条目转换失败时，点第 N 只会打开另一只
（不崩，但进错股）。

修法：在转换的同一轮里记 `代码.市场 → converted 下标`，兜底只查这份映射；
抽成 `DirectQuoteIndex` 纯函数并加 5 条单测（全成功 / 中间跳过 / 点击项被跳过 / 空列表 / 全失败）。

**自查问题**：这个列表有没有可能比原列表短？如果有，任何「按原下标取新列表」的代码都是 bug。

### 6.2 进程级失败标志必须带时间窗，不能是永久布尔

`SnapReadiness.kxResolveFailed` 一旦置位，整个进程生命周期内 K 线反射都返回 null，
只有 classLoader 变化才清。第一次进详情页太早、控件还没加载时，之后所有页面都退化成
「标题命中 + 静置 900ms」，就绪门禁形同虚设。

修法：改成 `kxFailedAt` + 30 秒退避窗口；窗口内不重试，窗口外允许再试一次，
仍失败继续退避；首次失败打 WARN，退避内的重复失败降 DEBUG。

**自查问题**：这个 `Boolean` 标志是不是「一次失败就永不恢复」？是的话换成时间戳。

### 6.3 还原类工具要能证明「备份属于当前对象」

`restore.mjs` 原来只校验「备份字节数 == 当前头长度」。跨 ZCode 版本时旧备份也能撞上
长度，写回去会让 asar 头里所有 `offset` 错位，直接损坏安装。

修法：除目标文件外逐条比对 `offset` / `size` / `integrity`；写回后 `fsync` 并重读校验
目标条目已恢复成普通条目；外部文件删不掉时 fail-closed；新增 `--dry-run` 先跑全部检查。

**自查问题**：这个备份是「尺寸对得上」还是「确实属于当前对象」？前者不够。

### 6.4 真机未验证要写在明面上

本轮两条 GSE 改动（坐标映射、就绪退避）**都没有真机复验**。CHANGELOG 与发布说明都
必须写明「真机未验证」，不能让人以为已经验证过 —— 这是本仓的红线，也是前几轮
「修完引入新 bug」的直接教训。
