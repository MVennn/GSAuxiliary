## 代码审查：查了什么、怎么修的

本版对模块做了一次系统性代码审查（两轮），下面是主要发现与修复。

**性能：滚动与高频回调的热路径**

- 策略页有一个「页面同步」功能，监听布局变化来同步模块自绘控件；原实现每次回调都对整棵视图树做全量遍历，而布局回调在滚动时每帧都来 —— 改成有实际动作后 1.5 秒冷却，空闲轮直接放行。
- 盯盘列表的每一行都会对整份「一键配置」方案 JSON 做哈希比对、并沿类继承链做全量反射扫描找宿主字段。改成：配置指纹在构造期算一次缓存；反射到的字段访问器按类缓存（含失败结果，避免反复白扫）；日 K 数据在同一会话内做记忆化，不再重复取数。
- 开启液态玻璃时，一级页背后常驻一块全屏「录制层」用来做折射取样 —— 非玻璃模式（简约版）下这层没有意义，改为按需挂载。
- 模块配置快照的「指纹」原实现每次读取都全量重算，改为构造期算一次；JS 自检周期从 500ms 放宽到 1500ms，回调先做廉价判断再做全量扫描。

**稳定性：生命周期与越权**

- **热重载残留**：重载模块后关闭开关，导航条染色、隐藏的视图、底栏按钮还原不掉 —— 因为旧功能实例被直接丢弃，没人执行「关闭」动作。改成卸载钩子前先给旧实例分发一份「全关」配置快照，走每个功能自己现成的关闭还原路径，并保证清理先于新注入。
- **JS 桥越权**：页面里的第三方脚本能通过模块注入的 `gsaux` 桥驱使原生收起 Activity 栈、拉起模块设置页。给相关桥方法补上「仅价格页 URL 可用」的守卫，诊断信息截断 200 字符并限频；个股代码在所有 INFO 及以上日志里脱敏（`300045.1` → `30****.1`）。
- **运行中补装**：启动时未启用的功能会被永久跳过，运行中打开开关必须重启宿主。改成维护一张「已装功能表」，配置变化时对「没装过 && 本轮已启用」的功能就地补装钩子；安装失败就从表里移除，下次配置变化还有机会重试。
- 一批泄漏与边界：策略详情 Activity 泄漏、旧实例残留在 ListView 上的适配器拆不掉、列表越界时 `getView` 拿到非法下标会把宿主打崩、配置导出时同一份快照被全表重建 28 次（改为取一次循环用）—— 全部修复。

**正确性：取数与交互逻辑**

- **取数校验绕过**：宿主行情通道靠「代码回显」确认页面确实是当前这只股票；原实现读不到代码字段时直接放行，宿主改版后会把上一只股票的价格写进方案。改成读不到就视为无法校验、降级不用缓存。
- **全选误触**：自选页「全选」靠行数计数判断状态；计数读不到时原实现把「已全选」状态点成「全部取消」。改成计数不可信时逐行探测。
- 中危 3 条与低危 10 条（观察器撤除时机、并发初始化窗口、子进程超时先温和终止再强杀、死代码清理等）逐条清零，清单见 CHANGELOG。
